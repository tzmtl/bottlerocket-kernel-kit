## Runtime acceptance

The forced rebuild was locked into downstream Bottlerocket source commit
`4c587ac89c2bb5ad529ead645a2fd07d3aebae2b` and published as private AMI
`ami-0b71b0e46fd3e60ba` in AWS account `225989333724`, region `us-west-2`, for
`aws-k8s-1.33-nvidia`.

On A10G, the AMI booted Bottlerocket 1.64.0 with kernel 6.18.38 and selected the
Tesla/proprietary 580.82.07 driver. Automatic `nvidia_drm`, DRI, ordinary GPU
allocation, `nvidia-smi`, Vulkan, native NVMe binds, SELinux enforcing, and the
task-owned privileged-opener -> confined-generator -> distinct-MCS-consumer
input-device fd path passed. The pre-existing shared input generator remained
unchanged and reproduced the expected `MSG_CTRUNC` negative control because its
live template lacks the explicit host `/dev/uinput` `CharDevice` mount.

The approved L40S node group never obtained an EC2 instance. Its managed update
exhausted retries with `InsufficientInstanceCapacity` in its configured
`us-west-2a`, `us-west-2b`, and `us-west-2c` subnets. No L40S boot or runtime
claim is made. EKS returned the group to its exact zero-scaled baseline, and the
temporary candidate launch-template version was deleted.

## Security status

The three compatibility versions are intentionally retained to reproduce
existing production images. NVIDIA 570 is end-of-life, and 580.82.07 and
595.58.03 predate the fixes present in 580.159.03 and 595.71.05. Treat AMIs
using these versions as compatibility artifacts until the downstream need is
reviewed; do not infer production security approval from a successful build.
